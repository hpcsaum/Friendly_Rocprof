# Plan 4.3: fold OpenMP runtime frames into the user function that owns the parallel region

Branch: `fix-openmp-runtime-frames` (from `master` at `620d115`, 4.x line — a bugfix).

## Context

The sampling hotspots table merges rows **by label across the whole call tree and all ranks**
(`scan_ranks()`/`aggregate()` key on `(label, gpu)`). OpenMP's runtime frames are generic, so every
parallel region in the program collapses into the same few rows. A CPU parallel region looks like:

```
FUNC                                       (user routine containing "!$omp parallel ...")
 └─ __kmpc_fork_call                       (libomp)
     └─ __kmp_fork_call
         └─ __kmp_invoke_microtask         <- self 1.07s of 4.58s inclusive in the reported case
             └─ FUNC..omp_par.97           (compiler-outlined region body — a distinct label, fine)
```

(Reproduced with `amdflang` 22 / ROCm 7.2.4; the stack is identical with `OMP_NUM_THREADS=1`.)
`__kmp_invoke_microtask` therefore shows up as one generic top hotspot summing the runtime-side
residue (fork/join cost, barrier waits) of **every** region, hiding which region and which routine
it belongs to. Worker threads add more: they sit in `start_thread → __kmp_launch_worker →
__kmp_launch_thread → … → __kmp_wait*`, idle-spinning, which would also rank as "hotspots".

Nothing in the tool handles OpenMP runtime frames today (no `kmp`/`gomp` pattern anywhere in
`default_noise_patterns.json`, the stage3/stage5 code, or the test fixtures). No local real run
contains these frames either (the six `test_apps/results` runs have none), so the fix is validated on
synthetic fixtures plus a compiler-built reproducer, and the user's real file is the final check.

### What the compiler tests showed (amdflang 22 / amdclang, ROCm 7.2.4, `gdb` stacks; this machine)

Compiled one construct per program (parallel, parallel do, do static/dynamic, sections, single, master,
critical, atomic, barrier, workshare, task, taskgroup, reduction, simd, loop, teams distribute parallel do,
ordered; `taskloop` in C — flang 22 does not implement `taskloop` at all):
- **Every CPU construct** is `__kmpc_fork_call → __kmp_fork_call → __kmp_invoke_task_func →
  __kmp_invoke_microtask → <outlined body>`. All other constructs' runtime calls (`__kmpc_for_static_*`,
  `dispatch_*`, `barrier`, `single`, `master`, `critical`, `reduce`, `ordered`, `omp_task*`, `taskgroup`,
  `fork_teams`) happen **inside** that outlined body, so they are children of the region's row. `atomic` has
  no runtime call; `simd`/`loop`/`workshare`/`sections` lower to static worksharing.
- **Tasks:** the task body runs *below* runtime frames:
  `region_body → __kmpc_omp_taskwait|__kmpc_barrier → [kmp_flag_64<false,true>::wait →
  __kmp_hyper_barrier_release →] __kmp_execute_tasks_* → __kmp_invoke_task → <task body>`; reparenting the
  task body to the region body (what `splice_by_tag` does) is exactly right.
- **Spinning workers:** `start_thread → __kmp_launch_worker → __kmp_launch_thread → __kmp_invoke_task_func →
  __kmp_invoke_microtask → __kmpc_barrier → __kmp_barrier → __kmp_hyper_barrier_release →
  kmp_flag_64<false,true>::wait → __kmp_hardware_timestamp`. **`kmp_flag_64<…>::wait` has no `__kmp` in its
  name** — the leaf where spinning happens — so the pattern must include plain `kmp_`.
- **Sleeping workers** (after the spin/blocktime): the chain continues `__kmp_suspend_64 →
  ___pthread_cond_wait → __pthread_cond_wait_common → __futex_abstimed_wait_common64`. Those libc frames do
  not match any libomp pattern and survive as reparented rows. **Out of scope for this plan** (see below).
- **Outlined-body names differ per compiler and are not a "parallel region" marker:** flang names
  *every* outlined body `<parent>..omp_par[.N]` — task bodies and teams bodies too, numbered in reverse
  source order; clang: `<fn>.omp_outlined[_debug__]`, `.omp_task_entry.[.N]`; gfortran: `<fn>._omp_fn.N`.
  These are the user's work and are never matched.
- **libgomp (GCC):** only `GOMP_parallel` was verifiable here; this machine's libgomp is stripped, so
  worker frames came out as `??`. `gomp_` coverage is therefore best-effort and untested on real data.

User's design choice (asked): **fold into the owner** — runtime time is attributed to the user function
containing the region; `..omp_par.N` rows stay their own hotspots; worker-thread idle spinning is dropped.

## Design

1. **New tag `openmp_runtime`** in `postprocess/stage6/default_noise_patterns.json`:
   `{"substrings": ["kmp_", "kmpc_", "gomp_"]}` (matching is lowercase). `kmp_` covers `__kmp_*`,
   `_INTERNAL…__kmp_…` and the C++ class methods like `kmp_flag_64<…>::wait`; `kmpc_` covers
   `__kmpc_*` (the compiler-facing entry points, which `kmp_` alone would miss); `gomp_` covers libgomp's
   `GOMP_*`/`gomp_*`. Public API names (`omp_get_*`) and every compiler-outlined body name
   (`..omp_par`, `.omp_outlined`, `.omp_task_entry.`, `._omp_fn`) deliberately do NOT match — those are the
   user's work. Known false-positive risk: a user symbol containing `kmp_`/`kmpc_`/`gomp_` (e.g. a Fortran
   module `kmp_mod`) would be folded away; `--extra-noise-config` can `remove` the substring or `disable`
   the tag (also the raw-tree escape hatch, same as `sampler_signal_frame`). Cray's own OpenMP runtime
   symbols could not be checked.

2. **Extend the existing `splice_by_tag(rows, tag, fold=True)`** in
   `postprocess/stage3/stage3_rocprofsys_common.py` with two new optional parameters, defaults chosen so
   every existing caller (`other`, `wrapper_noise`) behaves exactly as today:
   `splice_by_tag(rows, tag, fold=True, into_owner=False, skip_tags=())`
   - `skip_tags`: a row is only treated as matched when it carries `tag` AND none of `skip_tags`
     (a small `is_matched(row)` predicate replaces the bare `tag in row["tags"]` checks, used for both
     `walk_skip` and the removal filter). At the new call sites `skip_tags={"gpu_api", "mpi_territory"}`
     so a row that also carries one of those keeps its existing handling (e.g. host-side offload runtime
     rows stay in the GPU-API bucket).
   - `into_owner=True` (only meaningful with `fold=True`) switches the fold to "attribute to the owning
     user function": the removed row's **`self_sum` only** is added to the owner (the owner's inclusive
     `sum` already contains it, so `sum` is left untouched — unlike today's `fold=True`, which also adds
     `sum`; that existing, tested behavior for the `other` tag is not changed), and it is **discarded
     instead of folded** when the owner is a thread root (`owner["is_thread_root"]`) or there is no owner
     — worker-thread startup/idle/wait time between regions, not work attributable to a user routine.
     The reparenting of surviving children is the existing `walk_skip` logic, unchanged.
   - Runs AFTER `tag_rows()` (needs `row["tags"]`). Docstring updated to describe both parameters.

3. **Wire into both sample-pipeline loaders**, right after `tag_rows()` (same two call sites as plan 4.2), as `splice_by_tag(rows, "openmp_runtime", fold=True, into_owner=True, skip_tags={"gpu_api", "mpi_territory"})`:
   - `postprocess/stage4/stage4_rocprofsys_sample_flat.py` `scan_ranks()`: after `root_sum` is taken from
     the unspliced rows (so `total_runtime` cannot change), splice before the noise-drop loop.
   - `postprocess/stage4/stage4_rocprofsys_sample_tree.py` `load_rank_trees()`: before the `postprocess`
     hook, so the call-tree tools (`extract_calltree`, `extract_wallclock_calltree`) and
     `extract_hotspot_callers` (which reuses `load_rank_trees`) all see the same folded view.
   Not touched: the trace-CSV pipeline (different data), `extract_pop_metrics` logic (it goes through
   `scan_ranks`, so it inherits the fold — verify its numbers don't change on the existing fixtures).

4. **Docs:** `postprocess/README.md` (stage3 paragraph + customizing section), root `README.md`
   noise-filtering sentence; note the Cray caveat and that barrier waits inside a region end up on the
   region's `..omp_par.N` row (their nearest owner).

## Known limits (documented, not fixed here)

- **Granularity is the outlined body, not the directive**: `single`, `critical`, `barrier`, `reduction`, a
  static `do` loop and their waits all land on the same `..omp_par.N` row. Telling directives apart needs
  source lines (`gdb -batch -ex "break <outlined name>"` with `-g`).
- **Waits inside a region count as that region's self time** (nearest owner), so load imbalance shows up as
  extra self time on `..omp_par.N`, not as a separate row.
- **Sleeping-worker libc frames** (`___pthread_cond_wait`, `__futex_abstimed_wait_*`) beneath
  `__kmp_suspend_*` are not touched; whether to fold libc wait leaves that sit under runtime frames is a
  follow-up to decide on real data from the user's run.
- Worker-thread time attributed to a thread-root owner is discarded (spinning/launch overhead).
