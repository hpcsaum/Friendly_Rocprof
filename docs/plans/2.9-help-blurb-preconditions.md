# Plan 2.9: HELP_BLURB precondition updates (roadmap step 8)

## Context

Roadmap step 9 (§10 applied uniformly) introduces a "redirect" rule: a report's general/
methodology caveats get replaced with one line pointing to `--help`, instead of being repeated in
every report — but only where `--help` already says the same thing, or the redirect would silently
delete information. §10's own precondition audit (docs/plans/2.1-postprocess-consolidation-
refactor.md §10, "Precondition for rule 5") already checked this line-by-line and found exactly two
gaps, both named explicitly there:

- **`extract_calltree.py`** — 4 of its 6 `Caveats:` footer bullets already overlap `HELP_BLURB`
  closely enough to redirect safely later. 2 don't exist there yet: (a) which tree-surgery action
  applies to which noise tier (wrapper frames → spliced out, MPI internals → collapsed, GPU-API/
  compiler-runtime → pruned), and (b) the compiler-runtime tier being built from Cray's Fortran
  runtime specifically, not verified against other compilers.
- **`extract_pop_metrics.py`** — its `Caveats:` footer block (the MPI-classification-is-heuristic
  caveat, the CPU↔GPU per-rank pairing assumption) isn't in `HELP_BLURB` at all yet. Its
  `Not computed:` block is already there almost verbatim, so no change needed for that part, and its
  `Metric explanation:` block is a per-shown-column legend rather than general background, so rule 5
  doesn't apply to it either.

This step is **additive only**: add the missing content to each tool's `HELP_BLURB`. It does not
touch, shorten, or redirect the reports' own `Caveats:` footer text — that deletion only happens in
step 9, once every tool's `--help` is confirmed to say everything the report currently spells out
inline. Roadmap dependency: none (§12 row 8 says "could happen any time earlier"); verification is
a manual read-through, not real-data diffing, since no report output changes in this step.

## Approach

### `postprocess/extract_calltree.py`

Current `HELP_BLURB`'s second paragraph (lines 53–63) names the four `--show-*` flags and what
they reveal, but not *how* each tier is hidden by default. Add two sentences to that paragraph,
reusing the exact wording already in the report's own `Caveats:` footer (`write_report()`, in this
same file) so the two stay consistent:

```
...Four independent flags
reveal each of these, hidden by default: --show-gpu-api,
--show-rocprofsys-internals, --show-mpi-internals, --show-compiler-runtime
(or --show-all-internals for all four at once). Wrapper frames are spliced
out (children reparented, not deleted); MPI internals are collapsed (the
first real MPI frame is shown, its own internals are not); GPU-API and
compiler-runtime noise are pruned (whole subtree hidden). The compiler-
runtime tier was built from Cray's Fortran runtime specifically -- not
necessarily complete for other compilers, since none have been observed in
this project's data so far.
```

`extract_calltree_traced.py` is a separate tool with its own `HELP_BLURB` and its own, shorter
Caveats list (GPU-API hide/show is its only noise tier) — not in scope here; the master plan names
only `extract_calltree.py`'s two gaps.

### `postprocess/extract_pop_metrics.py`

Add a new paragraph to `HELP_BLURB` (after the existing "This does NOT compute..." paragraph, before
the "Under the hood..." closing paragraph) covering the same two caveats as the report's own
`Caveats:` footer. The footer's MPI-prefix sentence is built dynamically from `TAG_DEFS` at report
time (`TAG_DEFS['mpi_territory']['prefixes']`/`['suffixes']`); `TAG_DEFS` is already loaded at
module level (line 22) before `HELP_BLURB` is defined (line 24), so `HELP_BLURB` becomes an
f-string and embeds the same live values, rather than hand-duplicating today's prefix list as
static prose that could silently drift from `TAG_DEFS` later:

```python
HELP_BLURB = f"""\
...(existing paragraphs unchanged)...

Communication time is classified by function-name prefix (case-insensitive:
{', '.join(TAG_DEFS['mpi_territory']['prefixes'])}) or Fortran-shim suffix
({', '.join(TAG_DEFS['mpi_territory']['suffixes'])}) -- MPICH/Cray-MPICH
prefixes are confirmed from real captured data; the Open MPI prefixes are a
probable addition, not yet confirmed against a real Open MPI run. CPU<->GPU
per-rank pairing (when a rocprofv3 directory is given) assumes matching
sorted-filename order between the two directories -- not cross-checked.

Under the hood, ...
"""
```

Exact line-wrapping to match the file's existing ~75-column convention; content matches the
footer's wording closely (not verbatim-identical, since HELP_BLURB is prose read once up front and
the footer is a bulleted per-report caveat, but no information is dropped or altered).
