# Plan 2.16: reorganize `postprocess/` into one directory per stage + a `tools/` directory

## Context

`postprocess/` has grown to 29 Python files (plus `default_noise_patterns.json`) sitting flat in
one directory, and `postprocess/tests/` mirrors that with 30 flat test files. The stage-based
architecture (stage1 parsing → stage2 ancestry → stage3 noise classification → stage4
merge/aggregate → stage5 tables/rendering → stage6 report assembly) built up over plans 2.1–2.15 is
real and load-bearing, but invisible from the file listing itself — everything is named
`stageN_*.py` but lives in one undifferentiated directory alongside the 9 CLI tools
(`extract_*.py`/`select_*.py`). This plan makes the directory structure reflect that architecture:
one subdirectory per stage, one `tools/` subdirectory for the CLI tools, mirrored in `tests/`.

Confirmed by direct inspection of every `from stageN_x import y` / `import stageN_x` /
`import extract_X as x_tool` line in the codebase: the import graph is genuinely cross-cutting
(stage5 imports from stage1–4, stage4 imports from stage1–3, stage3 imports from stage6, every
tool imports from most stages and from other tools) — no stage is "downstream-only," so any
reorg must keep every stage's modules mutually importable, not just each tool's own direct deps.

**Chosen approach** (per your answer): relocate files only, keep every filename exactly as it is
today (e.g. `stage1/stage1_rocprofsys.py`, not `stage1/rocprofsys.py`). This means **zero import
statement changes** anywhere in source or test files — every existing `from stage1_rocprofsys
import X` keeps working unchanged, because Python resolves it by module name against `sys.path`,
not by directory. The only new code is a tiny shared bootstrap that puts every stage/tools
directory on `sys.path`. This was verified end-to-end with a throwaway spike (a miniature
stage1+tools+tests tree in `/tmp`) before committing to this plan — both `python3 -m unittest
discover -s tests` and dotted invocation (`python3 -m unittest tests.stage1.test_x`) work
correctly with this layout, provided each `tests/` subdirectory gets an `__init__.py` (required
for `discover`'s recursion into subdirectories in this Python version — bare namespace packages
were NOT picked up by `discover`, confirmed by the spike returning 0 tests without them).

## The bootstrap: `postprocess/_stage_paths.py` (new)

```python
"""Adds every postprocess/stageN/ and postprocess/tools/ directory to sys.path, once, so every
source and test file's existing flat "from stage1_rocprofsys import X"-style imports keep
resolving no matter which subdirectory the importing file itself lives in. Import this only after
putting postprocess/'s own absolute path on sys.path (see any tool or test file for the one-line
pattern) -- this module finds its sibling directories via its own __file__, so it works
regardless of who imports it or from where."""

import glob
import os
import sys

_ROOT = os.path.dirname(os.path.abspath(__file__))
for _dir in sorted(glob.glob(os.path.join(_ROOT, "stage*"))) + [os.path.join(_ROOT, "tools")]:
    if _dir not in sys.path:
        sys.path.insert(0, _dir)
```

**Every one of the 9 tool files** gets 2 new lines inserted after its existing `import os`/`import
sys` (before its first `from stageN_x import y` line):
```python
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
import _stage_paths  # noqa: E402  (adds every stageN/ dir to sys.path)
```
Tool-to-tool imports (`import extract_CPU_hotspots as cpu_tool`, used by 4 tools) need no change:
Python auto-adds a directly-run script's own directory to `sys.path`, and all 9 tools stay
co-located in `tools/`, so that sibling import keeps resolving exactly as today.

**Every one of the 30 test files** gets its existing single-line
`sys.path.insert(0, os.path.abspath(POSTPROCESS_DIR))` replaced by the same pattern, with
`POSTPROCESS_DIR`'s `".."` bumped to `"..", ".."` (one more directory deep now) plus the new
`import _stage_paths` line, e.g.:
```python
POSTPROCESS_DIR = os.path.join(os.path.dirname(__file__), "..", "..")
sys.path.insert(0, os.path.abspath(POSTPROCESS_DIR))
import _stage_paths  # noqa: E402
```
Two other mechanical, per-file adjustments across the same 30 files (same depth-by-one-more
pattern, no logic change):
- `FIXTURES = os.path.join(os.path.dirname(__file__), "fixtures")` → add one more `".."` (fixtures
  stays at `tests/fixtures/`, unchanged; the test file itself is now one level deeper).
- `MODULE_PATH = os.path.join(POSTPROCESS_DIR, "some_module.py")` (used by every test that loads
  its target via `importlib.util.spec_from_file_location` instead of a plain import — 9 tool
  tests plus `test_stage1_rocprofsys.py`/`test_stage1_rocprofv3.py`/`test_stage2_rocprofsys.py`/
  `test_stage4_rank_merge_math.py`) → insert that module's new stage/tools subdirectory into the
  join, e.g. `os.path.join(POSTPROCESS_DIR, "stage1", "stage1_rocprofsys.py")` or
  `os.path.join(POSTPROCESS_DIR, "tools", "select_hotspot_functions.py")`.
