# Plan 2.3: extract rank_merge_math.py (roadmap step 2)

## Context

`docs/plans/2.1-postprocess-consolidation-refactor.md` §7/§8 found that `aggregate_node_stats()`
(`calltree_common.py`) and the two `compute_load_imbalance()` copies (`extract_CPU_hotspots.py`,
`extract_GPU_hotspots.py` -- confirmed byte-for-byte identical except their docstrings) all
independently compute the same thing: avg/std_dev/min/max across a list of per-rank values, with a
missing rank counted as 0 rather than omitted. §12's roadmap makes extracting that shared core step
2 -- independent of step 1 (already landed) and of the stage-3 engine work, zero risk, verified by
byte-identical output.

An Explore pass verified every call site and the exact bodies before this plan was written.

## Approach

**New `postprocess/rank_merge_math.py`** with a fresh top-of-file docstring (scope/functions/
philosophy) and one function:
```python
def stats_across_ranks(values):
    """avg/std_dev/min/max across a list of per-rank values -- an empty list (no ranks to
    compare) returns all zeros rather than raising. std_dev uses statistics.pstdev()
    (population, not sample): every rank that exists is already the whole population being
    compared, not a sample drawn from a larger one."""
    if not values:
        return {"avg": 0.0, "std_dev": 0.0, "min": 0.0, "max": 0.0}
    return {
        "avg": statistics.mean(values),
        "std_dev": statistics.pstdev(values),
        "min": min(values),
        "max": max(values),
    }
```

**Scope note:** only the stats *math* moves, not the surrounding label-discovery/sort/selection
logic in `compute_load_imbalance()` (that function itself relocates to the stage-5 table modules in
roadmap step 6, per §8) -- so the two `compute_load_imbalance()` copies stay in their current files
this step, each just calling the shared primitive once per label instead of inlining
`statistics.mean()`/`pstdev()`/`min()`/`max()`.

**`calltree_common.py`'s `aggregate_node_stats()`** calls `stats_across_ranks()` three times (once
per `counts`/`selfs`/`totals` list), taking only `["avg"]` for `calls_avg`/`total_avg` (unchanged --
it never reported std_dev/min/max for those two). Its docstring's line "std_dev uses
statistics.pstdev() ... same choice extract_CPU_hotspots.compute_load_imbalance() already made,
kept consistent here rather than reinvented" gets cut -- that cross-file justification is moot once
both literally call the same function; consistency is now structural, not a comment's claim.

**Both `compute_load_imbalance()` copies** call `stats_across_ranks(values)` once per label instead
of the three inlined `statistics.*`/`min`/`max` calls, then build the same `entries.append({...})`
dict (adding the `label` and derived `cv_pct` fields) and keep their sort/`show_all`/`threshold`/
`top` logic verbatim -- purely an internal swap, output unchanged. The GPU copy's docstring
currently claims "duplicated rather than imported, matching this module's existing
stand-alone-by-design relationship" -- update it to state the new, accurate, partial reality: the
stats math is now shared via `rank_merge_math.stats_across_ranks()`, only the surrounding
selection/sort logic remains a standalone copy (until step 6 relocates the whole function).

**Implementation checkpoints (verify, don't assume):** confirm `import statistics` becomes unused
in `calltree_common.py`/`extract_CPU_hotspots.py`/`extract_GPU_hotspots.py` after this change (each
file's only use was inside the function being edited, per the Explore pass -- but grep to be sure
before removing the import from each).

**Tests:** add `postprocess/tests/test_rank_merge_math.py` testing `stats_across_ranks()` directly
(empty list -> all zeros; a normal multi-value list -> correct avg/std_dev/min/max; a single-value
list -> std_dev is 0). Leave `AggregateNodeStatsTests` (`test_calltree_common.py`) and both
`ComputeLoadImbalanceTests` (`test_extract_CPU_hotspots.py`, `test_extract_GPU_hotspots.py`)
unchanged -- they test the still-unchanged public behavior of the functions that now call the new
shared primitive internally, per §11's "split" category (new primitive test + thin existing
wrapper tests, not a relocation of the wrapper tests themselves).
