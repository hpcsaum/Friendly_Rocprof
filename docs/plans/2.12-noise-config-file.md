# Plan 2.12: user-facing noise-config file (roadmap step 10)

## Context

Roadmap step 10 (`docs/plans/2.1-postprocess-consolidation-refactor.md`, stage-3 engine design
section, lines 874-899) already designed this feature when the engine itself was first planned:
`--extra-noise-config PATH` / `$FRIENDLY_ROCPROF_NOISE_CONFIG` lets a user add/remove substring
patterns on the engine's 5 built-in noise tags, disable a tag entirely, and populate a reserved
`"other"` tag for their own app's noise that doesn't fit any built-in category — without editing
Python. This plan is that design's as-built implementation.

**Revised twice after review**: an initial draft threaded an optional `tag_defs` parameter through
every function between a tool's `main()` and `tag_rows()` — real, but unsustainable signature churn
for one process-wide setting, since every real invocation of this codebase is a single, one-shot
CLI process with exactly one noise-pattern configuration for its whole run. The resolved patterns
are **global, not threaded**, held by a new small stage-6 module. Second revision:
`load_default_patterns()` itself **moves out of `stage3_rocprofsys.py` into that same new
module**, rather than staying in stage3 with the new module importing it — this makes the
dependency strictly one-directional (stage3 reads from stage6; stage6 reads from nothing else in
this package), instead of stage6 needing stage3's loader while stage3 needs stage6's resolved
value.

## Approach

### 1. `stage6_noise_config.py` (new) — owns loading AND resolving the process-wide tag_defs

```python
"""Owns default_noise_patterns.json's bundled loading and resolves the noise-pattern definitions
every stage-3-consuming tool shares for the lifetime of one process, from an optional user diff
file layered on top of it.

Scope: the one place default_noise_patterns.json (or a user's own diff file) is read.
stage3_rocprofsys.py's tag_rows() reads the result via tag_defs() -- a plain one-directional
dependency (stage3 -> stage6), never the reverse, and no other module in this package reads either
file directly. A process-wide global, not threaded as a parameter through every function between a
tool's main() and tag_rows() -- every real invocation of this codebase is a single, one-shot CLI
process with exactly one noise-pattern configuration for its whole run, so a module-level singleton
is simpler and just as correct as parameter-threading.

Functions: load_default_patterns(), configure(), tag_defs().
"""
import json
import os

DEFAULT_PATTERNS_PATH = os.path.join(os.path.dirname(__file__), "default_noise_patterns.json")

_TAG_DEFS = None


def load_default_patterns(path=None):
    """The bundled tag -> pattern-definition mapping (see stage3_rocprofsys.py's module docstring
    for the schema)."""
    with open(path or DEFAULT_PATTERNS_PATH) as f:
        return json.load(f)


def configure(extra_config_path=None):
    """Resolves and stores the final tag_defs for this process -- called once, early, by each CLI
    tool's main() right after parsing --extra-noise-config/$FRIENDLY_ROCPROF_NOISE_CONFIG. Safe to
    call again (e.g. between tests, to reset or change the active config) -- always fully replaces
    any prior value, never merges with it.

    extra_config_path's diff schema: {"add": {tag: [substring, ...]}, "remove": {tag: [substring,
    ...]}, "disable": [tag, ...]}. add/remove only ever touch a tag's own "substrings" list (not
    prefixes/suffixes/ancestor rules -- those govern more structural matching behavior than a
    simple "does this text appear" tweak needs). disable is resolved first and always wins: a
    disabled tag is dropped entirely, and any add/remove naming it is then a no-op, not an error.
    Raises SystemExit for an unknown tag name anywhere, or for add/remove targeting a purely
    derived tag (currently just wrapper_branch_noise -- it has no self-scope patterns to tweak,
    only disable is meaningful for it).
    """
    global _TAG_DEFS
    patterns = load_default_patterns()
    patterns.setdefault("other", {"substrings": []})
    if extra_config_path is not None:
        _apply_diff(patterns, extra_config_path)
    _TAG_DEFS = patterns


def tag_defs():
    """The current resolved tag_defs -- lazily configured with no override on first use, so any
    caller that never touches configure() (every existing test, any tool run without
    --extra-noise-config) sees exactly today's bundled defaults, unchanged."""
    if _TAG_DEFS is None:
        configure(None)
    return _TAG_DEFS


def _apply_diff(patterns, extra_config_path):
    with open(extra_config_path) as f:
        diff = json.load(f)
    disable = set(diff.get("disable", []))
    for tag in disable:
        if tag not in patterns:
            raise SystemExit(f"error: {extra_config_path!r}: unknown noise tag {tag!r} in \"disable\"")
    for tag in disable:
        patterns.pop(tag, None)

    patterned = {name for name, td in patterns.items() if "sibling_group_source_tag" not in td}
    for op in ("remove", "add"):
        for tag, substrings in diff.get(op, {}).items():
            if tag in disable:
                continue
            if tag not in patterned:
                raise SystemExit(
                    f"error: {extra_config_path!r}: {op} targets {tag!r}, which isn't a known "
                    "pattern tag (derived tags like wrapper_branch_noise have no patterns to "
                    f"{op}; only \"disable\" applies to them)"
                )
            existing = patterns.setdefault(tag, {}).setdefault("substrings", [])
            if op == "remove":
                patterns[tag]["substrings"] = [s for s in existing if s not in substrings]
            else:
                existing.extend(substrings)
```
Placed as its own new file rather than growing `stage6_report_builder.py` — that module's own
scope is specifically report text assembly (header/footer/`render_report()`), a different concern
from loading/resolving input-side configuration.

### 2. `stage3_rocprofsys.py` — `load_default_patterns()`/`DEFAULT_PATTERNS_PATH` move out entirely

Deleted from `stage3_rocprofsys.py` (now owned solely by `stage6_noise_config.py`, see above); its
module docstring's mention of `load_default_patterns()` updated to point there instead.
`extract_pop_metrics.py` — the only other current importer, using it just to read
`mpi_territory`'s prefixes/suffixes into its own static `HELP_BLURB` text — updates its import to
`from stage6_noise_config import load_default_patterns`. (This keeps showing the *bundled* list in
`--help`, unchanged from today, since `HELP_BLURB` is already built once at module import time,
before any config could be parsed either way — reflecting a live custom config in `--help` text
would be a real enhancement, but out of scope here, and not a regression: it never did this
before.)

`tag_rows()` gains its fallback:
```python
def tag_rows(rows, tag_defs=None, filename=None):
    if tag_defs is None:
        tag_defs = stage6_tag_defs()
    ...  # unchanged below
```
with `from stage6_noise_config import tag_defs as stage6_tag_defs` at the top of the file — a
plain, non-circular import now that `stage6_noise_config.py` no longer needs anything from
`stage3_rocprofsys.py` in return. Every existing test that hand-builds a synthetic `tag_defs` dict
and passes it explicitly is completely unaffected — the fallback only engages when a caller omits
the argument.

This is a deliberate exception to the usual stage-N-depends-only-on-lower-N layering: `stage3`
(engine) reads from `stage6` (composition) here, because CLI/env-var resolution is inherently a
process-wide, cross-cutting concern, not business logic that flows upward through the pipeline.

### 3. Delete the two now-redundant per-file globals

`stage4_rocprofsys_flat.py` and `stage5_tree_render.py` each currently do
`TAG_DEFS = load_default_patterns()` at module import time and pass `TAG_DEFS` explicitly to their
own `tag_rows()` call. Both globals are deleted; both call sites become `tag_rows(rows,
filename=path)` (dropping the second positional argument entirely) and pick up
`stage6_noise_config.tag_defs()`'s current value automatically via `tag_rows()`'s own fallback.
**No other function signature in `stage4_rocprofsys_flat.py`, `stage5_tree_render.py`,
`stage5_calltree_view.py`, `stage5_calltree_traced_view.py`, or `stage5_pop_metrics_table.py`
changes at all** — `scan_ranks()`, `aggregate()`, `aggregate_per_rank()`, `load_rank_trees()`,
`build_calltree_view()` (both), `compute_run_metrics()` and its 2 helpers all stay exactly as they
are today.

### 4. `"other"`'s default treatment — same per-tool split `wrapper_noise` already has

The design says `"other"` "defaults to splice (with fold) everywhere unless a tool overrides it."
Per tool's own data shape (already how `wrapper_noise` is treated differently between flat and
tree tools today) — none of these need a `tag_defs` parameter either, since they call the same
already-fixed `tag_rows()`/`splice_by_tag()` functions:

- **`stage4_rocprofsys_flat.scan_ranks()`** (flat merge-by-label; feeds CPU hotspots, combined
  hotspots, pop_metrics, `select_hotspot_functions.py`): add `or "other" in row["tags"]` to the
  existing drop condition (same line that already drops `wrapper_noise`/`compiler_runtime_noise`)
  — there's no tree left to splice into by this point, the same reason `wrapper_noise` is dropped
  here instead of spliced.
- **`stage5_calltree_view.strip_wrapper_noise()`** (sampling calltree's postprocess hook): add
  `return splice_by_tag(rows, "other", fold=True)` after the existing `wrapper_noise` splice —
  same hook, same per-rank timing, splice+fold this time (matching the design's stated default,
  distinct from `wrapper_noise`'s own `fold=False`).
- **`stage5_calltree_traced_view.py`** (traced calltree): currently has no postprocess hook at all.
  Add a small `_splice_other(rows)` postprocess doing exactly `splice_by_tag(rows, "other",
  fold=True)`, passed to its `load_rank_trees()` call — `"other"` support lands "everywhere" as the
  design states, without introducing unrelated wrapper-noise handling this tool never had.

### 5. CLI wiring — `--extra-noise-config`, falling back to `$FRIENDLY_ROCPROF_NOISE_CONFIG`

Every tool whose output depends on CPU-side tagging gets the flag: `extract_CPU_hotspots.py`,
`extract_hotspots.py`, `extract_calltree.py`, `extract_calltree_traced.py`, `extract_pop_metrics.py`,
and `select_hotspot_functions.py`'s `--output-dir` mode (its `--report` mode reads an
already-rendered report file — tagging already baked in — so combining it with
`--extra-noise-config` raises a clear error, the same mutually-exclusive-group convention this tool
already uses for `--report`/`--output-dir`). `select_hotspot_kernels.py` and
`extract_GPU_hotspots.py` are untouched — neither imports `stage3_rocprofsys` (GPU kernel data has
no CPU-side noise classification to tune).

Each tool's `main()`, right after `parser.parse_args(argv)`, before any real work:
```python
parser.add_argument("--extra-noise-config", dest="extra_noise_config", default=None,
                     help="path to a JSON file customizing noise-tag patterns (add/remove "
                          "substrings, disable a tag) -- see stage6_noise_config.py's configure() "
                          "for the file schema; falls back to $FRIENDLY_ROCPROF_NOISE_CONFIG "
                          "if not given")
...
stage6_noise_config.configure(args.extra_noise_config or os.environ.get("FRIENDLY_ROCPROF_NOISE_CONFIG"))
```
That's the entire integration — `write_report()`/`labels_from_output_dir()` and everything they
call need zero changes to support this.

## Tests

- New `test_stage6_noise_config.py`: `configure(None)`/`tag_defs()` with no prior call returns the
  bundled defaults plus an empty `"other"`; `add` extends a tag's substrings (an existing tag and
  `"other"` itself); `remove` excludes named substrings; `disable` drops a tag entirely and makes
  any `add`/`remove` naming it a no-op; unknown tag name in any of the three raises `SystemExit`;
  `add`/`remove` targeting `wrapper_branch_noise` (purely derived) raises `SystemExit`, but
  `disable` on it succeeds; calling `configure()` again fully replaces the prior resolved value
  (doesn't merge). Every test that calls `configure()` resets it via `addCleanup(stage6_noise_config.configure, None)`
  so the process-wide global doesn't leak into unrelated tests running afterward in the same suite.
- `test_stage3_rocprofsys.py`: one new test confirming `tag_rows(rows, filename=...)` (no `tag_defs`
  given) falls back to `stage6_noise_config.tag_defs()`'s current value — configure a custom
  `"other"` pattern, confirm a matching row gets tagged; existing tests (all of which pass an
  explicit hand-built `tag_defs`) are completely unaffected.
- `stage4_rocprofsys_flat.py` / `stage5_calltree_view.py` / `stage5_calltree_traced_view.py`: one
  new test each confirming a `configure()`-set `"other"` pattern actually reaches that tool's own
  treatment (dropped from `aggregate()`'s output; spliced+folded out of the rendered tree for both
  calltree tools).
- Each of the 6 CLI-facing tools' own test file: `--extra-noise-config` end-to-end (a small
  hand-written JSON fixture disabling `compiler_runtime_noise`, confirming previously-excluded rows
  now appear); `$FRIENDLY_ROCPROF_NOISE_CONFIG` env var fallback (one test, on whichever tool is
  simplest to exercise it through); `select_hotspot_functions.py`'s `--report` +
  `--extra-noise-config` combination raises a clear error.
- Run the existing full suite first per this project's established practice — every default path
  (`tag_defs()` never explicitly `configure()`d) should need zero changes, since nothing about the
  existing call chain's signatures changed.
