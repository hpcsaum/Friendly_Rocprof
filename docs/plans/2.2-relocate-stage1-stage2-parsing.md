# Plan 2.2: relocate stage 1+2 parsing/ancestry functions (roadmap step 1)

## Context

`docs/plans/2.1-postprocess-consolidation-refactor.md` mapped the whole `postprocess/` codebase
and found that `parse_table_file()`, `clean_label()`, `thread_id_from_raw_label()`, `PID_SUFFIX_RE`,
and `attach_ancestry()` are general-purpose rocprof-sys text-table parsing/ancestry logic that only
happens to live inside `extract_CPU_hotspots.py` for historical reasons — three other tools already
reach into that file via `cpu_tool.*` just to get at them. Same story for `parse_kernel_stats_csv()`
in `extract_GPU_hotspots.py`. §8 of that doc puts these in three dedicated modules
(`stage1_rocprofsys.py`, `stage1_rocprofv3.py`, `stage2_rocprofsys.py`); §12's roadmap makes this
step 1 — zero-risk, zero-behavior-change, verified by byte-identical real-data output — the
foundation the riskier stage-3/stage-4 work (steps 4-5) builds on later.

An Explore pass verified every call site and dependency before this plan was written (see below);
nothing here is guessed.

## Approach

**Create three new modules**, each with a fresh top-of-file docstring per `CLAUDE.md`'s Code
Comments rule (scope / functions / philosophy — current behavior only, no history). Every
moved function/constant also gets its own comments rewritten against the same rule, not carried
over verbatim — below is the exact before/after for each one that needs a change (two of the five
function docstrings are already clean and move unchanged; every constant comment gets rewritten):

- `postprocess/stage1_rocprofsys.py` — owns `PID_SUFFIX_RE`, `EXPECTED_HEADER_FIELDS`,
  `FIXED_FIELDS_AFTER_LABEL`, `parse_table_file()`, `clean_label()`, `thread_id_from_raw_label()`.

  `PID_SUFFIX_RE` — before: *"rocprof-sys's default per-process file naming is `"<component>-<pid>.txt"` -- used as a fallback rank count (one file per process/rank) when metadata.json lacks a count."* After (tightened, same fact, less winding):
  ```python
  # Matches rocprof-sys's per-process filename pattern "<component>-<pid>.txt" -- used to
  # group files by rank, and as a fallback rank count when metadata.json has none.
  PID_SUFFIX_RE = re.compile(r"-(\d+)\.txt$")
  ```

  `EXPECTED_HEADER_FIELDS`/`FIXED_FIELDS_AFTER_LABEL` — before: *"COUNT..% SELF -- everything after LABEL. Kept as a count, not the literal names, because under MPI the docs describe the row prefix as `"|MM|NN>>>label"` -- an embedded pipe that would otherwise misalign a naive fixed-column split."* After (states the constraint plainly instead of assuming the reader already knows what "kept as a count" refers to):
  ```python
  # The table's header row, matched as one fixed block rather than by individual field name:
  # a row's LABEL can itself contain a literal "|" (MPI's rank/thread prefix is
  # "|MM|NN>>>label"), which would misalign a naive per-field column split.
  EXPECTED_HEADER_FIELDS = [...]
  FIXED_FIELDS_AFTER_LABEL = len(EXPECTED_HEADER_FIELDS) - 1
  ```

  `parse_table_file()`, `clean_label()`, `thread_id_from_raw_label()` — docstrings already state
  current behavior only, no history to strip — move unchanged.

- `postprocess/stage2_rocprofsys.py` — owns `attach_ancestry()`. Before, the docstring's second
  paragraph: *"General-purpose: this is the reusable first step for a future real call-tree view (walk `"parent"` links to render nesting/indentation), not specific to any one classification decision -- classify_gpu() below is just its first consumer."* — this is about the function's role/journey in the codebase, not what it does (and "below" is now false, since classify_gpu stays in another file). Cut that paragraph entirely; keep only the first paragraph, which already describes current mechanism and mutation cleanly:
  ```python
  def attach_ancestry(rows):
      """Reconstruct each row's parent in the call tree from DEPTH + file order
      (rows already arrive in call-tree pre-order) via a depth-stack walk: a
      row's parent is the most recent prior row at depth-1. Mutates rows in
      place, adding "parent" (a reference to the parent row dict, or None at a
      true root) and "is_thread_root" (True when this row's thread_id differs
      from its parent's -- i.e. this row is where a new OS thread's own subtree
      begins in this file's listing, right after whatever call spawned it).
      """
  ```

- `postprocess/stage1_rocprofv3.py` — owns `REQUIRED_COLUMNS`, `parse_kernel_stats_csv()`.

  `REQUIRED_COLUMNS` — before: *"Schema confirmed directly from rocprofiler-sdk's own source (generateCSV.cpp): only `"Name"` is quoted; numeric columns may be plain-decimal or scientific notation depending on magnitude -- Python's `float()`/`int(float())` handles both."* — "confirmed directly from rocprofiler-sdk's own source" is investigation-journey framing; the standing fact worth keeping is the format quirk itself:
  ```python
  # "Name" is the only quoted CSV field; numeric columns may be plain-decimal or
  # scientific notation depending on magnitude -- float()/int(float()) handles both.
  REQUIRED_COLUMNS = {"Name", "Calls", "TotalDurationNs"}
  ```

  `parse_kernel_stats_csv()` — docstring already states current behavior only — moves unchanged.

**Update every caller to import the moved names**, using `from <module> import name1, name2` (not
an aliased whole-module import) — matching `calltree_common.py`'s existing precedent, and critically
this means call sites inside `extract_CPU_hotspots.py`/`extract_GPU_hotspots.py` themselves need
*zero* changes beyond the import line, since the bare names stay valid in that module's own
namespace. It also means test files that access these through the module-namespace pattern
(`hotspots.attach_ancestry(...)`, etc. — confirmed as the *only* access pattern in every test file,
no test imports these names directly) keep working unchanged for every test that isn't itself being
relocated, since `from stage2_rocprofsys import attach_ancestry` re-binds `attach_ancestry` into
`extract_CPU_hotspots`'s own namespace too.

Concrete edits:
- `extract_CPU_hotspots.py`: delete the 6 moved things' definitions; add
  `from stage1_rocprofsys import PID_SUFFIX_RE, parse_table_file, clean_label, thread_id_from_raw_label`
  and `from stage2_rocprofsys import attach_ancestry`. (Its own separate, different `PID_SUFFIX_RE`
  question doesn't apply here — that constant only exists in `extract_GPU_hotspots.py`, untouched.)
- `extract_GPU_hotspots.py`: delete `parse_kernel_stats_csv()` and `REQUIRED_COLUMNS`; add
  `from stage1_rocprofv3 import parse_kernel_stats_csv`. Its own distinct `PID_SUFFIX_RE` (line 35,
  a different regex, used only by `guess_num_ranks()`) is untouched — out of scope for this step.
- `extract_calltree.py`: replace the 4 call sites (`cpu_tool.PID_SUFFIX_RE`,
  `cpu_tool.parse_table_file()`, `cpu_tool.attach_ancestry()`, `gpu_tool.parse_kernel_stats_csv()`,
  all inside `load_rank_trees()`/`_kernel_totals_with_counts()`) with the new direct imports. Every
  other `cpu_tool.*`/`gpu_tool.*` reference in this file (GPU_API_PREFIXES, MPI_PREFIXES,
  aggregate_per_rank, etc.) is stage 3/4 work — untouched, `cpu_tool`/`gpu_tool` aliased imports stay.
- `extract_calltree_traced.py`: same 4-call-site swap (also inside `load_rank_trees()`/
  `_kernel_totals_with_counts()`). `cpu_tool.classify_gpu()` in this file is stage 3 — untouched.

**Tests** (per §11's already-decided move-list):
- New `postprocess/tests/test_stage1_rocprofsys.py`: move `CleanLabelTests` and
  `ParseTableFileTests` out of `test_extract_CPU_hotspots.py`, pointing their
  `importlib.util.spec_from_file_location` loader at the new module.
- New `postprocess/tests/test_stage2_rocprofsys.py`: move `AttachAncestryTests` (the 4
  ancestry-mechanics tests) the same way.
- New `postprocess/tests/test_stage1_rocprofv3.py`: move `ParseKernelStatsCsvTests` out of
  `test_extract_GPU_hotspots.py` the same way.
- Every other test class that calls `hotspots.attach_ancestry(...)`/`hotspots.parse_table_file(...)`
  as setup for a *different* test (e.g. `ClassifyGpuTests`, `MarkWrapperContaminatedBranchesTests` —
  14 call sites total, confirmed by the Explore pass) needs no change, per the import-re-binding
  point above.
- Quick safety check during implementation: confirm no test references `EXPECTED_HEADER_FIELDS`,
  `FIXED_FIELDS_AFTER_LABEL`, or `REQUIRED_COLUMNS` directly by name (Explore didn't find any, but
  these weren't its primary target).
