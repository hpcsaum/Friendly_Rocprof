# Plan 2.5: stage-3 noise-filtering engine, built in isolation (roadmap step 4)

## Context

`docs/plans/2.1-postprocess-consolidation-refactor.md` §9 designs a shared "tag-then-act" engine
to replace today's ~15 independent, hand-written noise-classification functions spread across
`extract_CPU_hotspots.py`, `extract_calltree.py`, and `extract_calltree_traced.py`: separate
**classification** (is this row noise, which kind — one shared pass) from **treatment** (what to
do about it — each tool's own small map). §12's roadmap makes building this engine, on its own,
step 4 — explicitly **not wired into any tool yet** (that's step 5); verified by unit tests against
synthetic trees only, since there's no real tree to run it against until it's actually wired in.

Three Explore passes read every existing predicate in `extract_CPU_hotspots.py`, both calltree
tools, and `extract_pop_metrics.py` verbatim (not just the master plan's summary) before this plan
was written, to ground the new engine in what real code actually does today, including several
details the master plan's design section doesn't spell out:

- **Match types differ per tag, not just per constant.** `is_gpu_entry()` mixes a `startswith`
  check (`GPU_API_PREFIXES`) with a substring check (`GPU_COMPILE_NOISE_SUBSTRINGS`); `is_mpi_territory()`
  mixes `startswith` (`MPI_PREFIXES`) with `endswith` (`MPI_FORTRAN_SHIM_SUFFIXES`). The master
  plan's JSON sketch (§9) shows one flat substring list per tag — too simple; each tag needs its
  own prefixes/substrings/suffixes.
- **`extract_calltree.py`'s `GPU_NOISE_SUBSTRINGS` is a strict superset** of `extract_CPU_hotspots.py`'s
  GPU patterns (adds `rocprofiler::`, `cray_acc`, `hiphardwaredevice`, `present_table`,
  `pluginmanager::`, `devicety::`, `llvm::omp::target::plugin::`). A single shared
  `default_noise_patterns.json` necessarily ships the superset — this is one of the "2 tracked
  exceptions" roadmap step 5 already expects when wiring makes output change for the first time
  since step 1; nothing to reconcile in *this* step.
- **`.kd`-suffix matching is case-sensitive today** (`label.endswith(".kd")`, no `.lower()`) while
  every other check in the codebase lowercases first — an inconsistency, not a deliberate design
  choice. This plan normalizes it to case-insensitive, matching every other pattern type; real
  kernel-descriptor symbols are lowercase `.kd` by AMDGPU toolchain convention, so this has no
  practical effect on real data, but it's a small, intentional behavior change worth naming rather
  than silently carrying an inconsistency forward.
- **Two scopes are actually the same mechanism reused, not five independent algorithms.** The
  ancestor-walk in `classify_gpu()` (GPU) and `is_runtime_thread_noise()` (MPI) are structurally
  identical, just parameterized by tag — confirming §9's own point that first-real-descendant
  "generalizes a mechanism that already exists for GPU threads, just hardcoded to one tag."
  `mark_wrapper_contaminated_branches()`/`prune_wrapper_contaminated_branches()` (sibling-group) has
  **no pattern list of its own** — it's derived entirely from `wrapper_noise`'s already-computed
  subtree-match results, grouped by parent. This means sibling-group isn't "a tag with its own
  patterns," it's an operation parameterized by a *source* tag.
- **"Fold" genuinely doesn't exist today** — confirmed by reading `splice_out_wrapper_nodes()`
  line by line: a spliced wrapper node's own self-time is simply discarded, never added to its
  new parent. This plan is where that behavior first gets implemented, not just relocated.
- **`prune` and `structural_drop` are mechanically identical** — both mean "remove this row and
  its whole subtree from further processing." They differ only in *how* a row gets marked for
  removal (self/ancestor/first-real-descendant tag match vs. a sibling-group comparison), not in
  what removal does. One shared removal primitive covers both.
- **`GPU_FILE_HINTS`** (roctracer/hsa-named *files* force every row inside them to GPU, regardless
  of label) and the filename-level exclusions (`NON_TIMING_FILES`, `EXCLUDED_METRIC_FILE_PREFIXES`)
  operate on the source **file**, not the row's label or tree position — they don't fit any of the
  5 scopes (all are about a row's label/tree position) and stay **outside the engine entirely**,
  same as today: each tool keeps doing its own file-level filtering before rows ever reach the
  engine.
- **`extract_calltree_traced.py` really does have exactly one tier** (GPU-API + `.kd`, via
  `cpu_tool.classify_gpu()` directly) — confirmed by reading the whole file; no MPI/wrapper/
  compiler-runtime logic exists there at all today, consistent with the master plan's claim.
- **Test-coverage gap found**: no existing test anywhere directly exercises `is_mpi_territory()`'s
  `_f08_`/`_f08ts_` suffix branch as a unit assertion (the one real-looking fixture label,
  `mpi_allreduce_f08ts_`, is only checked for *rendering*, never fed to `is_mpi_territory()`
  directly). This plan's own tests close that gap for the new engine.

## Approach

**New `postprocess/default_noise_patterns.json`** — tag name → pattern definition. Four tags carry
real patterns (ported verbatim from the four Explore-confirmed constants); a fifth is a *derived*
tag with no patterns of its own, parameterized by a source tag instead:

```json
{
  "gpu_api": {
    "prefixes": ["hip", "hsa", "roctx", "kfd", "rocdecode", "rocjpeg", "rocr"],
    "substrings": ["clang::", "llvm::", "amd_comgr", "rocprofiler::", "cray_acc",
                   "hiphardwaredevice", "present_table", "pluginmanager::", "devicety::",
                   "llvm::omp::target::plugin::"],
    "suffixes": [".kd"],
    "ancestor_for_thread_roots": true,
    "first_real_descendant_skip_tag": "wrapper_noise"
  },
  "wrapper_noise": {
    "substrings": ["tim::", "gotcha", "rocprofsys", "__libc_start", "lookup_hashtable",
                   "lookup.constprop", "lib_bindings", "library_gots", "get_library", "get_tool",
                   "add_binding_to_tool", "create_hashtable", "lookup_exported_symbol",
                   "prepare_symbol"]
  },
  "mpi_territory": {
    "prefixes": ["mpi_", "pmpi_", "mpir_", "mpid_", "mpidi_", "ompi_", "opal_", "orte_"],
    "suffixes": ["_f08_", "_f08ts_"],
    "ancestor_for_thread_roots": true,
    "first_real_descendant_skip_tag": "wrapper_noise"
  },
  "compiler_runtime_noise": {
    "substrings": ["_f90_", "__allocate", "_dealloc", "posix_memalign", "_mid_memalign",
                   "_int_memalign", "_int_malloc", "_int_free", "sysmalloc",
                   "__default_morecore", "sbrk", "_fwf", "_xfer_iolist"]
  },
  "wrapper_branch_contamination": {
    "sibling_group_source_tag": "wrapper_noise"
  }
}
```
`suffixes` matches case-insensitively (lowercased label), like prefixes/substrings — including
`.kd`, normalized from today's accidental case-sensitivity (see Context). `mpi_territory` and
`gpu_api` both get `first_real_descendant_skip_tag: "wrapper_noise"` — this is
what closes §9's flagged gap ("calltree's missing MPI-thread-noise handling for untethered roots")
structurally: the same generic mechanism that already inherits `gpu_api` onto an untethered thread
root now does the same for `mpi_territory`, with no MPI-specific code anywhere.

**No `action` field anywhere in this file.** §9 is explicit that the same tag gets a different
action per tool ("calltree's `wrapper_noise → splice` vs. CPU hotspots' `wrapper_noise → drop`") —
action is a tool-supplied decision made when *wiring* the engine in (roadmap step 5), not a
property of the tag itself. This step only builds classification plus generic, reusable action
*primitives* (below) — no tool calls any of them yet.

**New `postprocess/stage3_rocprofsys.py`** — the engine. One public entry point:
```python
def tag_rows(rows, tag_defs):
    """Mutates every row in place: row["tags"] becomes a frozenset of every tag whose pattern
    matched this row's own label, or (for a thread-root row) any ancestor's label, or (for an
    untethered root) the first real -- non-wrapper -- descendant's tags. row["structural_drop_tags"]
    becomes a frozenset of tags for which this row's WHOLE SUBTREE should be removed because of a
    sibling comparison (see sibling-group below) -- kept separate from "tags" because it's a
    removal decision about a row, not a fact about what the row's own label looks like."""
```
Internally, four passes over one children-map (built once, per §9's stated goal of replacing
today's ~6 independent re-scans):
1. **Bottom-up** (post-order, memoized): for every patterned tag, `self_match` (from
   prefixes/substrings/suffixes, all matched against the lowercased label) and `subtree_has_match`
   (self OR any descendant).
2. **Top-down** (pre-order): `ancestor_match[row][tag] = self_match[parent][tag] or ancestor_match[parent][tag]`
   — the O(n) "riding the pre-order" recurrence §9 asks for, replacing today's O(depth)-per-row walk.
   A tag ends up in `row["tags"]` via ancestor scope only if `tag_defs[tag]["ancestor_for_thread_roots"]`
   and `row.get("is_thread_root")` and the tag is in `ancestor_match[row]`.
3. **Sibling-group derivation** (no new tree walk — reuses pass 1's `subtree_has_match`, grouped by
   `id(parent)`): for every tag with a `sibling_group_source_tag`, and every sibling group of size
   ≥2, mark a sibling for `structural_drop_tags` if its subtree has a match, at least one sibling in
   the group has none (a contaminated group needs a clean sibling to contrast against — matching
   `mark_wrapper_contaminated_branches()`'s `not any(matches) or all(matches): return` guard exactly),
   and the sibling's OWN label doesn't itself already carry the source tag (that simpler case is
   already covered by `self_match`, not this derivation).
4. **Untethered-root first-real-descendant** (only rows with `parent is None`): for every tag with a
   `first_real_descendant_skip_tag`, walk down through the FIRST child only (matching today's
   `kids[0]`-only behavior — not a new invariant, preserving the existing single-child-chain
   assumption) at each level, skipping any child whose `self_match` includes the skip tag, until a
   non-skip child is found or there are no more children; if that child's own `row["tags"]` (already
   fully computed by steps 1-3) includes the target tag, add it to the root's `row["tags"]` too.

**Generic action primitives** (the "5 actions," built here, called by nobody yet):
- `remove_tagged_subtrees(rows, tags)` — one shared removal primitive for **both** `prune` and
  `structural_drop` (confirmed mechanically identical in the Context section above): returns a new
  list with every row whose `tags` or `structural_drop_tags` intersects `tags`, plus its whole
  subtree, removed.
- `splice_by_tag(rows, tag, fold=True)` — generalizes `splice_out_wrapper_nodes()`: reparents every
  matched row's children up to its nearest non-matching ancestor, drops the matched rows, and (new)
  when `fold=True`, adds each removed row's own `self_sum`/`sum` into the ancestor its children got
  reparented to (the node that "absorbs" the removed wrapper's own real execution time instead of
  discarding it).
- `make_collapses_children(tags)` — returns a closure `lambda row: bool(tags & row.get("tags", ()))`,
  directly usable as `tree_render.build_children_map()`'s `collapses_children` argument.
- `make_is_pruned(tags)` — returns the tree-rendering-shaped equivalent (`lambda row: bool(tags &
  (row.get("tags", set()) | row.get("structural_drop_tags", set())))`) for tools that render a tree
  rather than physically filtering a flat list.
- **bucket** needs no primitive — it's just reading `tag in row["tags"]` directly (e.g. how CPU
  hotspots would route a row); documented in the module docstring, not implemented as a function.

**`load_default_patterns()`** reads the bundled JSON (`json.load` from the file next to this
module). No override-file loading (`--extra-noise-config`/`FRIENDLY_ROCPROF_NOISE_CONFIG`,
add/remove/disable) yet — that's roadmap step 10, which the roadmap itself lists as depending on
this step ("extends the engine's pattern loading"), not part of it.

**Fresh top-of-file docstring** for `stage3_rocprofsys.py` covering scope (classification +
generic action primitives; explicitly NOT wired into any tool, NOT the source of truth for what a
particular tool currently does — that only happens in roadmap step 5), the tag vocabulary, and the
philosophy (classification and treatment are separate; a tag is a fact about a row, an action is a
tool's decision about what to do with that fact).

## Tests

New `postprocess/tests/test_stage3_rocprofsys.py`, entirely synthetic trees (no fixture files, no
tool wiring exists to test against yet) covering, per tag/mechanism:

- **Self-scope matching**: prefix match (`gpu_api` via `hip...`), substring match (`wrapper_noise`
  via `gotcha`), suffix match (`mpi_territory` via `..._f08ts_`, closing the coverage gap found
  above; `gpu_api` via both `.kd` and `.KD`, proving the normalized case-insensitive suffix match).
- **Ancestor-for-thread-roots**: thread-root with a matching ancestor tags positive (`gpu_api` and,
  new, `mpi_territory`); non-thread-root row ignores a matching ancestor; a row's own direct match
  wins regardless of ancestry.
- **Sibling-group (`wrapper_branch_contamination`)**: contaminated sibling marked, clean sibling
  untouched; an uncontaminated linear (single-child, no real siblings) wrapper chain is NOT marked;
  a sibling whose own top label already matches `wrapper_noise` directly is excluded from this
  derivation (that's `self_match`'s job); all-contaminated or all-clean sibling groups untouched.
- **First-real-descendant on untethered roots**: `gpu_api` inherited through a `wrapper_noise`
  hop (mirrors existing behavior); **new** — `mpi_territory` inherited the same way, proving the
  generalization §9 flagged as an open question actually works mechanically (still noted, per §9,
  as unconfirmed whether this shape occurs in real data — this test proves the mechanism, not the
  real-world occurrence).
- **`remove_tagged_subtrees()`**: a tagged node and its whole subtree disappear from the flat list;
  siblings/ancestors untouched.
- **`splice_by_tag()`**: children reparented up past a matched chain (including the "whole ancestor
  chain matched → child becomes a new root" case); matched rows removed; and, new, `fold=True`
  correctly adds a removed wrapper node's `self_sum` into its nearest surviving ancestor (`fold=False`
  proves the old discard-it behavior is still available/opt-out).
- **`make_collapses_children()`/`make_is_pruned()`**: closures return correct booleans against
  hand-built rows carrying pre-set `tags`/`structural_drop_tags`.
- **`load_default_patterns()`**: loads the real shipped JSON and sanity-checks the 5 expected tag
  names are present.

## Implementation note

`.kd`-suffix matching was normalized to case-insensitive during implementation (folded into
`gpu_api`'s regular `suffixes` list, matched against the lowercased label) rather than kept as a
separate case-sensitive `exact_suffixes` mechanism as first drafted — simpler, and the case
distinction has no practical effect on real kernel-descriptor symbol names.

Full test count after implementation: 332 (306 existing + 26 new in `test_stage3_rocprofsys.py`).
