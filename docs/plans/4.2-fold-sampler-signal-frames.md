# Plan 4.2: fold sampler signal-handler frames into the interrupted function

Branch: `fix-sampler-handler-artifacts` (from `master`, 4.x line — this is a bugfix, not part of the 5.x work).

## Context

On a very recent ROCm, a real HPC run of `profile_CPU_hotspots.sh` produced a sampling call tree where
every sample's innermost frames are the sampler's own signal handler, hanging off the signal-return
trampoline:

```
... |_Fortran::runtime::InitializeTicket::Continue(...)        (self 0.0%)
      |_  ___restore_rt                                          (self 0.0%)
          |_ std::pair<std::_Rb_tree_iterator<int>, bool> std::_Rb_tree<int,...>  (self 100%)
```

Two real-data runs showed the consequence:

- With a user-local `std::pair` entry in `compiler_runtime_noise`, those rows were dropped and the
  hotspots table came out **empty** (480 s + 206 s of self time is ~99.8% of the run, and `scan_ranks()`
  drops noise rows together with their time).
- With that pattern removed, the table is a profile of the **sampler itself**: the two `std::pair<...>`
  rows hold 69.8% + 30.0% of self time, and every real application/runtime function shows ~0 self.

The sampler handler's frames (reached via `___restore_rt`, the libc signal-return trampoline) are never
application code. The correct attribution is the **interrupted function**: the row directly above
`___restore_rt`, whose inclusive `SUM` already contains the handler's time but whose `% SELF` is 0.

Intended outcome: the whole subtree under a signal-return trampoline is removed and its inclusive time
is added to the parent row's `self_sum`, in both the flat view (`scan_ranks`, used by hotspots / POP /
load-imbalance / fused ranking) and the call-tree view (`load_rank_trees`, used by calltree tools and
`extract_hotspot_callers.py`).

## Design

1. **New tag `sampler_signal_frame`** in `postprocess/stage6/default_noise_patterns.json`:
   `{"substrings": ["restore_rt", "rt_sigreturn"]}` (x86-64 libc `__restore_rt`, aarch64
   `__kernel_rt_sigreturn`). Living in the JSON means `--extra-noise-config` can already `add`/`remove`
   substrings or `disable` the tag, with no new CLI flag. `tag_rows()` will also stamp it on rows as an
   ordinary tag (harmless).

2. **New primitive in `postprocess/stage3/stage3_rocprofsys_common.py`:**
   `fold_signal_frame_subtrees(rows, tag_defs=None, label_key="label")`:
   - Matches rows with the existing `_label_matches()` against `tag_defs["sampler_signal_frame"]`
     (no-op if the tag is absent/disabled).
   - For each *topmost* matching row with a parent: `parent["self_sum"] += row["sum"]`
     (parent's `sum` is unchanged — it already includes it), then drop the row and its whole subtree
     (reuse `_build_children_map()`, same traversal as `remove_tagged_subtrees()`).
   - Nested matches: only the topmost is processed (inner time is already inside its `sum`).
   - A matching row with no parent (`parent is None`) is left untouched (nothing to attribute to).
   - Returns the new row list. Does not recompute `% SELF`-derived fields on other rows.
   - Runs **before** `tag_rows()`, deliberately: `tag_rows()`'s sibling-group `wrapper_branch_noise`
     comparison would otherwise see handler frames under `___restore_rt` (potentially
     `rocprofsys::...` frames) and could prune a whole real sibling subtree together with its time.
     Documented in the function's docstring and the module docstring's "Functions:" list.

3. **Wire it in at the two sampling-table entry points**, right after `attach_ancestry(rows)` and before
   `tag_rows(...)`:
   - `postprocess/stage4/stage4_rocprofsys_sample_flat.py` (`scan_ranks()`, ~line 88). Note `root_sum`
     is computed from raw row SUMs afterwards — use the post-fold rows; the root row's `sum` is
     unaffected by the fold so `total_runtime` is unchanged.
   - `postprocess/stage4/stage4_rocprofsys_sample_tree.py` (`load_rank_trees()`, ~line 73).
   Not touched: the trace-CSV pipeline (`stage3_rocprofsys_trace.py`, `stage4_rocprofsys_trace_*`) —
   different data source, no evidence of this artifact there; noted as out of scope.

4. **Behavior notes to document** (module docstring + `postprocess/README.md` stage3 section):
   an application's own `SIGxxx` handler running under a trampoline is also folded into the
   interrupted function — acceptable (that time is still attributed to the code that was running),
   and `disable: ["sampler_signal_frame"]` in an extra-noise-config restores the raw view.
