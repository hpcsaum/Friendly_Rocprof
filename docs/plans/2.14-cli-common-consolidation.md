# Plan 2.14: consolidate `main()`'s repeated argument-handling/setup steps (new, beyond the original roadmap)

## Context

Not part of the original 11-step roadmap — added at your request, immediately after step 11, having
just spent plan 2.12 copy-pasting near-identical `--extra-noise-config` blocks into 6 different
`main()` functions. A direct grep across all 8 CLI tool files confirms the duplication is real and
not limited to that one flag:

- **Directory-existence check** (`if not os.path.isdir(X): raise SystemExit(f"error: no such
  directory: {X!r}")`) — byte-identical in 6 of 8 files (`extract_CPU_hotspots.py`,
  `extract_GPU_hotspots.py`, `extract_calltree.py`, `extract_calltree_traced.py`,
  `select_hotspot_functions.py`, `select_hotspot_kernels.py`); `extract_hotspots.py`/
  `extract_pop_metrics.py` have their own multi-directory variants of the same check
  (`extract_pop_metrics.py` loops over `[reference_dir] + scaled_dirs`; `extract_hotspots.py`
  validates a resolved CPU+GPU pair). Both variants need to be one shared helper, not two, since
  future tools need both shapes too — the GPU-aware capstone tool (plan 2.15) needs the CPU+GPU
  pair shape, and any future pop_metrics-style scaling variant of another tool needs the N-directory
  shape.
- **`-n/--top` + `--threshold` + `--all` mutually-exclusive "selection" group** — appears in 4
  files (`extract_CPU_hotspots.py`, `extract_GPU_hotspots.py`, `select_hotspot_functions.py`,
  `select_hotspot_kernels.py`) with near-identical help text ("number of X to list/select
  (default: N)", "only list/select entries at or above this %% ...", "list/select every X, no
  truncation") differing only in the entry noun.
- **`--extra-noise-config` registration + env-var fallback + `configure()` call** — byte-identical
  help text in the 6 tools plan 2.12 added it to.
- **`--max-depth`** — byte-identical in both calltree tools (`extract_calltree.py`,
  `extract_calltree_traced.py`); the shape any future tree-rendering tool needs too.
- **`--show-*` noise-visibility flags** — `extract_calltree.py` has 4 (`--show-gpu-api`,
  `--show-rocprofsys-internals`, `--show-mpi-internals`, `--show-compiler-runtime`) plus a
  `--show-all-internals` shorthand; `extract_calltree_traced.py` has 1 of the same 4
  (`--show-gpu-api`, byte-identical help text to `extract_calltree.py`'s own). A future tool
  needing some subset of the same 4 tiers shouldn't have to hand-roll new copies of this text.
- **`-o/--output` dest resolution** (`args.dest or os.path.join(default_dir, "name.txt")`) — same
  shape in ~6 files, differing only in the default filename.
- **`command_header(sys.argv[0], tokens)` + trailing `print(f"wrote {dest}")`** — same shape in
  ~7 files (the `tokens` list itself is inherently tool-specific, since each tool has different
  flags, so only the wrapping mechanics unify, not the list contents).

## Approach

New module **`stage6_cli_common.py`**, a 4th narrowly-scoped stage-6 module alongside the existing
`stage6_report_builder.py`/`stage6_run_metadata.py`/`stage6_noise_config.py` (each already owns one
distinct "options + composition" concern; this one owns the argparse/validation boilerplate every
tool's `main()` repeats):

```python
def require_directory(path):
    """Raises SystemExit with this project's standard error message if path isn't a directory --
    the base check every tool's main() does on each of its own directory arguments."""
    if not os.path.isdir(path):
        raise SystemExit(f"error: no such directory: {path!r}")


def require_directories(paths):
    """require_directory() applied to every path in paths -- the shape every tool validating 2+
    required directories at once needs (a pop_metrics-style scaling study's reference + scaled
    dirs, a resolved CPU+GPU directory pair). None entries are skipped: an optional directory that
    wasn't given/resolved at all isn't an existence error by itself -- whether that's an error
    (extract_hotspots.py requires its GPU side to resolve to something) or fine (the calltree
    tools' GPU side is genuinely optional) is tool-specific business logic that stays in the
    caller, checked before or after this call as appropriate."""
    for path in paths:
        if path is not None:
            require_directory(path)


def resolve_dest(explicit_dest, default_dir, default_filename):
    """The -o/--output resolution every tool does identically: explicit_dest if given, else
    default_dir/default_filename."""
    return explicit_dest or os.path.join(default_dir, default_filename)


def add_selection_args(parser, entry_noun, threshold_unit_help, top_help_suffix=""):
    """Adds the -n/--top / --threshold / --all mutually exclusive group every ranked-table tool
    shares, wording tailored to entry_noun (e.g. "hotspots", "hotspot functions") and
    threshold_unit_help (e.g. "of total runtime"). Returns the group, in case a caller needs to
    add one more mutually exclusive option to it (select_hotspot_functions.py doesn't; documented
    here so a future caller isn't surprised it's possible)."""
    selection = parser.add_mutually_exclusive_group()
    selection.add_argument("-n", "--top", dest="top", type=int, default=None,
                            help=f"number of {entry_noun} to list{top_help_suffix}")
    selection.add_argument("--threshold", dest="threshold", type=float, default=None,
                            help=f"only list entries at or above this %% {threshold_unit_help}")
    selection.add_argument("--all", dest="show_all", action="store_true",
                            help=f"list every {entry_noun}, no truncation")
    return selection


def add_max_depth_arg(parser):
    """Adds --max-depth, the tree-truncation flag every tree-rendering tool shares."""
    parser.add_argument("--max-depth", dest="max_depth", type=int, default=None,
                         help="truncate the tree at this depth (default: unlimited, print the whole tree)")


NOISE_TIER_FLAGS = {
    "gpu_api": ("--show-gpu-api", "also show GPU-API/offload-runtime noise instead of hiding it"),
    "rocprofsys_internals": ("--show-rocprofsys-internals",
                              "also show rocprof-sys's own instrumentation/GOTCHA/dynamic-linker "
                              "frames instead of splicing them out"),
    "mpi_internals": ("--show-mpi-internals",
                       "also show MPI library internals below the first MPI frame, instead of collapsing them"),
    "compiler_runtime": ("--show-compiler-runtime",
                          "also show compiler-runtime allocator/intrinsic helper noise instead of hiding it"),
}


def add_noise_tier_args(parser, tiers, all_shorthand=False):
    """Adds one --show-<tier> flag per name in tiers (any subset/order of NOISE_TIER_FLAGS'
    4 keys), each setting dest="show_<tier>". If all_shorthand and len(tiers) > 1, also adds
    --show-all-internals as a shorthand for all of them at once (the caller's own code still
    decides how to combine it with the individual flags, same as extract_calltree.py does today)."""
    for tier in tiers:
        flag, help_text = NOISE_TIER_FLAGS[tier]
        parser.add_argument(flag, dest=f"show_{tier}", action="store_true", help=help_text)
    if all_shorthand and len(tiers) > 1:
        parser.add_argument("--show-all-internals", action="store_true",
                             help=f"shorthand for all {len(tiers)} --show-* flags above at once")
```
`--extra-noise-config`'s own argparse registration + `configure()`-from-args call move into
`stage6_noise_config.py` itself instead (co-located with the module that owns the behavior, not a
generic grab-bag): `stage6_noise_config.add_cli_argument(parser)` and
`stage6_noise_config.configure_from_args(args)` (the latter doing the
`args.extra_noise_config or os.environ.get(...)` + `configure()` call in one line at each tool's
`main()`). The final `command_header()`/`print(f"wrote {dest}")` tail stays per-tool as-is — each
tool's own `tokens` list assembly is genuinely tool-specific (different flags), and unifying just
the 2-line wrapper around it would obscure more than it saves.

Every one of the 8 tool files' `main()` is updated to call these instead of repeating the inline
code — a mechanical, per-file edit, not a design change: same flags, same help text (verified
identical before/after via `--help` diff), same validation, same behavior.
`extract_hotspots.py`/`extract_pop_metrics.py` switch their own hand-rolled multi-directory loops
to `require_directories()`; both calltree tools switch to `add_max_depth_arg()` and
`add_noise_tier_args()` (with `extract_calltree.py` passing all 4 tiers + `all_shorthand=True`,
`extract_calltree_traced.py` passing just `["gpu_api"]`). `select_hotspot_kernels.py`'s
`--all-dispatches` flag and `select_hotspot_functions.py`'s `--check-instrumented`/`--unfiltered`
flags stay tool-specific (genuinely unique to each), added alongside the shared
`add_selection_args()` group.

## Tests

- New `test_stage6_cli_common.py`: `require_directory()` (existing dir passes silently, missing
  dir raises `SystemExit` with the standard message), `require_directories()` (all-exist passes,
  one missing raises, `None` entries are skipped not treated as missing), `resolve_dest()`
  (explicit wins, falls back to default otherwise), `add_selection_args()` (the 3 options are
  correctly mutually exclusive, wording substitutes `entry_noun`/`threshold_unit_help` correctly),
  `add_max_depth_arg()` (flag parses to the right dest/type), `add_noise_tier_args()` (each tier
  subset adds exactly the right flags/dests, `--show-all-internals` only appears when
  `all_shorthand=True` and `len(tiers) > 1`).
- Each of the 8 tools' existing `MainCliTests`-style tests need zero behavioral changes (same
  black-box behavior) — confirmed by running the existing suite unchanged first; only add new
  coverage if the consolidation itself introduces a genuinely new shared code path worth testing
  once rather than 8 times (e.g. one `require_directory()`-focused test could replace what's
  currently ~6 duplicated "missing directory raises" tests, though duplicated *tests* for a shared
  *implementation* aren't a real problem — leave them if reducing them would lose per-tool CLI
  coverage).
- Real-data regeneration across all 6 `test_apps/results/` dirs: **expected fully byte-identical**
  (pure internal refactor, no behavior change) — a regression check via diff, not a review pass.
  Also diff every tool's own `--help` output before/after to confirm the consolidation didn't
  accidentally reword anything a real user would see.
