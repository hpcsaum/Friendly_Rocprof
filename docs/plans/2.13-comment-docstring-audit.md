# Plan 2.13: final comment-and-docstring audit (roadmap step 11)

## Context

Roadmap step 11, the last item in `docs/plans/2.1-postprocess-consolidation-refactor.md`'s roadmap
table: sweep every `postprocess/*.py` file for any comment that wasn't naturally rewritten by plans
1–10, and bring it in line with CLAUDE.md's Code Comments rules (describe current behavior, not
history; no `docs/plans/...` pointers, "confirmed via real data", "the old behavior was...", or bare
"rule N" references; every module docstring covers scope, exposed functions, and design
philosophy). This is a comment-only cleanup — **nothing here changes behavior**, confirmed by the
full test suite staying green and real-data output staying byte-identical throughout.

Three parallel audits (one per pipeline layer: tool-level `extract_*.py`/`select_*.py`,
`stage1`–`stage4`, `stage5`–`stage6`) read all 29 `postprocess/*.py` files in full. Findings below.

### Rule 3 (module docstring) gaps

- **`stage5_table_render.py`**: scope prose only narrates `select_entries()`/`render_table()`, silent
  on `wrap_trailing_label()`, `iter_table_rows()`, `pct_total_note()`, `ranking_note()` (its
  `Functions:` line already lists all 6 correctly — only the prose is thin). Expand the scope
  paragraph to cover all three responsibilities the module now actually has (rank/filter, render,
  wrap/reparse + legend-text generation).
- **8 tool-level files** (`extract_CPU_hotspots.py`, `extract_GPU_hotspots.py`, `extract_hotspots.py`,
  `extract_calltree.py`, `extract_calltree_traced.py`, `extract_pop_metrics.py`,
  `select_hotspot_functions.py`, `select_hotspot_kernels.py`): none has a `Functions:` line naming
  its own exposed symbols, unlike every `stage*.py` module in the package, which all follow this
  convention consistently (confirmed by both other audits — every `stage1`–`stage6` file has one
  that matches its actual exports). Add a `Functions: write_report(), main()` line (or that file's
  actual equivalent — some also expose `gather_run_info()`, `find_lost_functions()`, etc.) to each,
  matching the house convention, for real consistency rather than partial compliance.

All other 20 files' docstrings and comments were confirmed accurate and compliant — no changes.

## Approach

Straightforward, low-risk text edits — no logic changes, no test changes needed (the tests already
pass; this doesn't touch behavior). For each finding above: rewrite the comment/docstring text in
place per its fix direction, keeping surrounding formatting/line-wrap style consistent with the
file's own convention. Do this file-by-file rather than batching by finding type, so each file's
diff is reviewed as a coherent whole.
