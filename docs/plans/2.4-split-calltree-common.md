# Plan 2.4: split calltree_common.py into stage4_rocprofsys_tree.py, tree_render.py, and stage1_run_dirs.py (roadmap step 3)

## Context

`docs/plans/2.1-postprocess-consolidation-refactor.md` §8 splits `calltree_common.py` (500 lines,
19 functions/constants) into a stage-4 module (cross-rank tree merge + kernel attachment) and a
pure rendering module -- independent of steps 1-2 (already landed) and the stage-3 engine work,
zero risk, verified by byte-identical output. §12's roadmap makes this step 3.

An Explore pass re-read the file fresh (it was already touched once in plan 2.3) and traced every
internal call, every cross-file call site, and every test class before this plan was written --
both candidate groups are confirmed internally closed (no function in one group calls anything in
the other), so the split has zero logic risk, only import-surface changes.

**`resolve_run_dirs()` is not purely a calltree/rendering concern -- checked its actual callers
before placing it.** `grep`ing every call site turns up three tools, not two: `extract_calltree.py`
and `extract_calltree_traced.py` call the `calltree_common.py` copy, but `extract_pop_metrics.py`
has its own fully independent, byte-for-byte-identical copy (`extract_pop_metrics.py:58-72`) that
never imports from `calltree_common` at all -- this is §6 finding 1 in the master plan ("exists
twice, one copy silently unreachable from the other... this is the one pair in the whole codebase
where the duplication looks accidental rather than declared") and §7's move-list already settled
the fix: "delete pop_metrics' copy, import from calltree_common." Since we're already relocating
its only remaining real copy, this step closes that accidental duplicate at the same time, rather
than leaving `extract_pop_metrics.py`'s stale copy to keep silently drifting (§6 finding 8 calls
out that exact drift risk as the mechanism behind a real past bug, the `MPI_PREFIXES` divergence).

**Deviates from §8 on where it lands.** The master plan's target architecture put
`resolve_run_dirs()` in `tree_render.py` as "a deliberate exception" specifically to avoid a fourth
stage-4 micro-module. But it has zero coupling to rendering, trees, or merging -- it's pure
directory-resolution I/O that runs *before* any of stage 1's parsing even starts, and it now
serves three tools, not two. It gets its own single-function module, `stage1_run_dirs.py`, matching
the existing `stage1_rocprofsys.py`/`stage1_rocprofv3.py` naming (a "stage 1" concern in the sense
that it's resolving *where* to read from, not *what*'s in either format -- source-agnostic the same
way `rank_merge_math.py` is). After this plan is approved, add a short header note to
`docs/plans/2.1-postprocess-consolidation-refactor.md` pointing here for the actual final home,
per `CLAUDE.md`'s divergence-tracking convention -- the target-architecture diagram and the
`tree_render.py` row in §8 both need that pointer.

## Approach

philosophy) gets, verbatim, unchanged: `merge_rank_trees()`, `flatten_tree()`,
`aggregate_node_stats()`, `make_node_values()`, `attach_kernel_summaries()`, `kernel_owner_label()`,
`find_kernel_anchors()`, `_attach_kernel_group()`, `unattached_kernel_per_rank()`,
`make_kernel_node()`, `nearest_visible_ancestor()`, `is_kernel_launch()`, and the constant
`KERNEL_LAUNCH_LABEL_SUBSTRINGS`. Needs `from rank_merge_math import stats_across_ranks` (already
calltree_common.py's only external import, besides `os` which isn't needed here).

**New `postprocess/tree_render.py`** (fresh top-of-file docstring) gets, verbatim, unchanged:
`render_forest()`, `render_node()`, `get_children()`, `count_all_descendants()`,
`format_aligned_rows()`, `build_children_map()`, and the constant `REPORT_HEADERS`. No `os` needed
-- `resolve_run_dirs()` was the only user of it in the old file, and it's leaving (below).

**New `postprocess/stage1_run_dirs.py`** (fresh top-of-file docstring), one function, `import os`:
```python
def resolve_run_dirs(run_dir):
    """A "run" is one directory that may contain a rocprof-sys/ subdir (CPU timing) and/or a
    rocprofv3/ subdir (GPU kernel timing). Falls back to treating run_dir itself as the CPU dir
    when there's no rocprof-sys/ subdir (profile_CPU_hotspots.sh's un-nested layout). Returns
    (cpu_dir, gpu_dir_or_None) without checking either actually contains data -- that's each
    caller's own job."""
    cpu_subdir = os.path.join(run_dir, "rocprof-sys")
    gpu_subdir = os.path.join(run_dir, "rocprofv3")
    cpu_dir = cpu_subdir if os.path.isdir(cpu_subdir) else run_dir
    gpu_dir = gpu_subdir if os.path.isdir(gpu_subdir) else None
    return cpu_dir, gpu_dir
```
The docstring merges both existing copies: `extract_pop_metrics.py`'s version adds "Returns
(cpu_dir, gpu_dir_or_None). Does not check either actually contains data -- see
compute_run_metrics()'s own empty-input handling" -- a genuinely useful invariant, kept here made
caller-agnostic instead of naming one specific caller.

**Fix `extract_pop_metrics.py`'s duplicate as part of this move:** delete its local
`resolve_run_dirs()` definition (lines 58-72) and add `from stage1_run_dirs import resolve_run_dirs`
to its import block. No call-site changes inside that file -- it already calls the function by its
bare name.

## Implementation note

During implementation, deleting `test_calltree_common.py` (which had loaded `calltree_common.py`
first among the alphabetically-sorted test files) surfaced a latent, undocumented cross-file
ordering dependency: `test_extract_CPU_hotspots.py` and `test_extract_GPU_hotspots.py` never
inserted `postprocess/` onto `sys.path` themselves, silently relying on some earlier-loaded test
module (previously `test_calltree_common.py`) to have done it first as a side effect of Python's
shared, process-wide `sys.path`. Both files now do their own `sys.path.insert()`, matching the
pattern already used by every other test file that plain-imports a sibling module (e.g.
`test_extract_hotspots.py`) -- removing the hidden ordering dependency rather than papering over it
by, e.g., restoring alphabetical placement.
